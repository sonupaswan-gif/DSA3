Full-Text Search Engine on a Suffix-Array Index

Data Structures and Algorithms – 3 (25CS2103E) · K L (Deemed to be) University

1. Load documents

Separate documents with a line containing only ---. You can also load .txt files; each file becomes one document.

2. Search

Search is case-sensitive. Substring: pattern anywhere. Prefix: pattern at the start of a word. Phrase: whole words in order. Results are ranked by number of occurrences.

3. Compare with an inverted index

Times the current query and query type on both indexes. Values come from your browser, so they change from run to run.

How it works

All documents are joined into one text. A suffix array is built by prefix doubling in O(n log² n), and the LCP array is built with Kasai's algorithm in O(n). A query is located by two binary searches (lower and upper bound) that remember how many characters already match the left and right boundary suffixes, so each comparison resumes from the smaller of the two. All matching suffixes then sit in one block of the suffix array; they are grouped by document and ranked by occurrence count.
